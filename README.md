# 🚀 AI Agent Architect Journey

> 거대 모델의 지능에 기대지 않고, 프롬프트 구조와 아키텍처 설계만으로 AI의 사고 과정을 통제하는 PM이 되기 위한 12주 학습 기록.
> 논문 한 편을 읽을 때마다 "이 구조를 실제 서비스에 적용하면 어디서 병목이 생기는가"를 산업공학적 관점에서 분석하고, 작은 Micro-Service로 구현해 남긴다.

## 🧭 Phase별 상세

### Phase 1 — 추론 엔진의 설계자
> **목표 상태:** "거대 모델에 의존하지 않고, 프롬프트 구조만으로 AI의 사고 과정을 통제하여 복잡한 비즈니스 의사결정 로직을 설계할 수 있다."

- **Attention Is All You Need** — AI가 문장에서 무엇에 '집중'하는지의 원리 → [`상세 보기`](./phase1-reasoning-engine/01-attention-is-all-you-need)
- **Chain-of-Thought** — "차근차근 생각하라"로 정답률을 높이는 사고법
- **ReAct** — 생각 → 행동 → 관찰 → 재사고 루프 (에이전트의 뼈대)

### Phase 2 — 외부 데이터·도구의 지휘자
> **목표 상태:** "할루시네이션을 해결하고, 사내 DB나 외부 API를 AI의 팔다리처럼 연결하는 인터페이스를 설계할 수 있다."

- **RAG** — 외부 지식을 검색해 답변 근거로 삼기 (AI의 도서관)
- **Toolformer** — "지금은 계산기/검색이 필요해"를 스스로 판단 (AI의 도구함)
- **Generative Agents** — 경험을 기억·저장했다 꺼내 쓰기 (AI의 장기 기억)

### Phase 3 — 품질 최적화 아키텍트
> **목표 상태:** "사람이 검수하지 않아도 에이전트가 스스로 결과물을 비판·수정하는 '자율 개선 루프'를 구축해 신뢰도를 보장할 수 있다."

- **Reflexion** — "왜 별로지?"를 자문하고 다시 시도하는 루프 (자기 객관화)
- **Self-Instruct** — 적은 데이터로 스스로 학습 데이터를 만들어 성능을 높이기

### Phase 4 — 멀티 에이전트 조직의 CEO
> **목표 상태:** "복잡한 프로젝트를 작은 태스크로 쪼개고, 각 태스크에 최적화된 에이전트 팀을 구성해 협업시킬 수 있다."

- **MetaGPT** — 기획자·개발자·디자이너 '페르소나'를 부여해 협업 (AI 회사 설계)
- **ChatDev** — 가상의 SW 개발 단계를 에이전트들이 릴레이로 수행 (AI 워크플로우)

## 🏭 이 과정이 증명하려는 것 (KPI)

단순 취업 준비가 아닌 **'AI 기반 시스템 최적화 전문가'**로서의 기초와 실제 업무에 적용할 수 있는 것이 목표다.

1. **기술 포용력** — 최신 논문을 보고 48시간 안에 서비스에 붙일 수 있는 Micro-Service로 프로토타이핑한다.
2. **한정 자원 구현** — 유료 모델을 난사하지 않고 가벼운/오픈소스 모델로 워크플로우를 짜 비용을 최대 80%까지 절감한다.
3. **산업공학적 관점** — 에이전트의 각 단계를 공정(Process)으로 보고, 어디서 병목이 생기는지 데이터로 분석해 개선한다.

## 📖 학습 방법 — AI 샌드위치 독서법

요약에만 중독되지 않기 위해, '직접 읽기'와 'AI 활용'을 번갈아 겹친다.

1. **1 · 직관 잡기 (직접)** — Abstract와 Figure 1만 보고 "내 눈엔 이게 어떻게 작동하는 시스템인가"를 1~2문장으로 메모.
2. **2 · 골격 세우기 (NotebookLM)** — 핵심 병목, 기존 기술 대비 차별점, 에이전트 설계에의 시사점을 질문해 전체 지도를 그림.
3. **2 · 정밀 타격 (직접)** — AI가 짚어준 핵심 섹션만 한 줄씩 정독해 저자의 논리 디테일을 직접 파악.
4. **2 · 백지 설명 (직접)** — 구체적인 논리 및 수식, 전체 흐름을 나의 언어로 풀어서 설명. 
5. **3 · AI 구현 (Claude 및 생성형 AI)** — 백지 설명을 기반으로 AI를 활용하여 논문 구현
